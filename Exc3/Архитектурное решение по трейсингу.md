## Составьте список данных, которые должны попадать в трейсинг

Мониторить надо прохождение заказа по статусной модели.
Выделил такие пути для трейсинга заказа. Важно понимать время изменения статуса заказа, самое критичное это отлеживать операции обновления в shop db.
Полагаю, что основная просадка на уровне обработки 3d processing(MES API) и дальше сообщения могут попадать в DLQ в Message Queue.
- shop api-> shop db
- crm api -> shop db
- crm api -> message queue
- mes api -> message queue
- mes api -> mes db

Список данных которые попадают в tracing:
 - HTTP Requests (shop site → shop API → CRM API)
 - sql запросы (shop API → ShopDB, CRM API → ShopDB)
 - события шины (shop API → RabbitMQ → MES API)
 - Background worker (MES API processing the order)
 - Обновления статусов (MES API → MES DB → CRM API → Shop DB, shop api->shop db )

Частью tracing может стать order_id и user_id

## Мотивация 
Внедрение distributed tracing позволит компании получить полную видимость бизнес-процессов, улучшить стабильность системы и повысить скорость реагирования на инциденты.
Трассировка поможет понимать, где происходят задержки, где сбои, и какие сервисы требуют оптимизации.

Метрики:

1. Время обработки заказа (Бизнес)
Как быстро заказ проходит от момента оформления до завершения.
Помогает сократить время обработки заказа, улучшая SLA для клиентов.

2. Время отклика ключевых API (Техника)
Среднее время обработки запросов в Shop API, CRM API, MES API.
Показывает задержки на уровне API и БД.
Позволяет анализировать нагрузку на систему и эффективность SQL-запросов.

3. Доля успешных и неуспешных запросов (Техника)
Процент ошибок в API и очередях сообщений.

4. Производительность очередей (Техника)
Среднее время обработки сообщений в RabbitMQ (от публикации до обработки в MES API).

5. Конверсия заказов (Бизнес)
Процент заказов, которые успешно доходят до MES API и операторов.

## Компромиссы 

1. API-USER -> MES API тут вероятно не надо отдавать tracing наружу.
2. В случае с S3, end-to-end tracing сложно реализовать ибо это стороння система должно мочь пробрасывать tracing обратно. Поэтому тут можно реализовать tracing только на уровне shop api.

## Аспекты безопасности. 

1. OAuth2-Proxy поставить перед Jaeger
2. Identity Server валидирует токены с ролями
3. OAuth2-Proxy позволяет только роли Админ вызывать UI Jaegger
4. Jaeger доступен пользователям с ролью Админ
