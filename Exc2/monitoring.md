### Мотивация

1. Более быстрое решение проблем и повышение надёжности системы. С помощью инструментов наблюдения команда может быстрее определить корень проблемы. Следовательно, так её проще устранить и предотвратить в будущем.

2. Повышение быстродействия системы и распределение ресурсов. С помощью инструментов наблюдения можно выявлять узкие места. Это помогает оптимизировать производительность — вы можете проанализировать, как система работает под разными нагрузками.

3. Ускорение рабочего процесса и DevOps. Наблюдаемость способствует оптимизации процессов и сокращению количества ошибок. А это, в свою очередь, помогает ускорить рабочий процесс и улучшить взаимодействие между командами.

4. Ценные бизнес-инсайты. Когда данные, которые вы собираете благодаря наблюдаемости системы, накапливаются, они могут привести вас к бизнес-инсайтам. Они помогут вам принимать стратегические решения более обоснованно.

5. Повышение удовлетворённости пользователей. Своевременное решение проблем, которые связаны с производительностью и функциональностью приложения, улучшает пользовательский опыт.
6. Ошибки напрямую влияют на взаимодействие с потребителями. Следовательно, отслеживать частоту ошибок просто необходимо.
   
7. Быстрее диагностировать и решить проблему.

### Выбор подхода к мониторингу

*Выберите, какой подход к мониторингу вы будете использовать: RED, USE или «Четыре золотых сигнала». Для разных частей системы можно использовать разные подходы.*

1.  USE (Utilization, Saturation, Errors)

Где используется: Инфраструктура (EC2, базы данных, RabbitMQ).
ShopDB, MES DB, MES API, 3dfilestorage ShopApi
Utilization: загрузка CPU, RAM, диска.
Saturation: очереди сообщений в RabbitMQ, перегруженные ресурсы Облака.
Errors (Ошибки): сбои сервисов, ошибки баз данных.

2.  RED 

Обычно на уровне Api Gateway и когда система более нагружена. А так можно было прикрутить для MES API ибо он стал открыт для интеграций и для SHOP API.
Можно посмотреть на аномалии, всплески, но не приоритетно.
- Rate (Частота запросов): количество входящих API-запросов.
- Errors (Ошибки): процент ошибочных API-запросов.
- Duration (Время ответа): среднее время отклика API.

3. Четыре золотых сигнала (Latency, Errors, Traffic, Saturation)
Пользователи жалуются что страницы долго грузятся, можно применить этот подход
Где используется: Онлайн-магазин, CRM.
Latency (Задержки): время загрузки страниц, выполнения запросов.
Errors (Ошибки): критические ошибки в системе.
Traffic (Трафик): количество активных пользователей, нагрузка на сервисы.
Saturation (Насыщенность): доступность ресурсов, проблемы с масштабируемостью.


### Опишите, какие метрики и в каких частях системы вы будете отслеживать. 

Number of dead-letter-exchange letters in RabbitMQ
Зачем нужна: Позволяет отслеживать сообщения, которые не могут быть обработаны и попадают в DLX. Может указывать на ошибки в обработке сообщений.
Ярлыки: очередь (queue), сервис (service).

Number of message in flight in RabbitMQ
Зачем нужна: Показывает количество сообщений, находящихся в обработке. Высокие значения могут сигнализировать о задержках в потреблении сообщений.
Ярлыки: очередь (queue), сервис (service).

Number of requests (RPS) : shop API / CRM API / MES API
Зачем нужна: Позволяет мониторить нагрузку на API, выявлять пиковые периоды и потенциальные проблемы с производительностью.
Ярлыки: сервис (service), метод (method)

CPU % for shop API / CRM API / MES API
Зачем нужна: Показывает загрузку процессора, позволяет отслеживать рост нагрузки и необходимость масштабирования.
Ярлыки: сервис (service), инстанс (instance).

Memory Utilisation for shop API / CRM API / MES API
Зачем нужна: Позволяет выявлять утечки памяти, а также следить за доступностью ресурсов.
Ярлыки: сервис (service), инстанс (instance).

Memory Utilisation for shop db instance / MES db instance
Зачем нужна: Анализирует использование памяти баз данных, помогает обнаруживать узкие места.
Ярлыки: база данных (db_name), инстанс (instance).

Number of connections for shop db instance / MES db instance
Зачем нужна: Позволяет контролировать количество соединений с базой данных, предотвращая исчерпание соединений.
Ярлыки: база данных (db_name), инстанс (instance).

Response time (latency) for shop API / CRM API / MES API
Зачем нужна: Измеряет задержку ответа API, помогает выявлять проблемы с производительностью.
Ярлыки: сервис (service), метод (method).

Size of S3 storage
Зачем нужна: Показывает объем хранимых данных, помогает отслеживать рост использования хранилища.Ярлыки: бакет (bucket_name).

Size of shop db instce / MES db instance
Зачем нужна: Контролирует размер баз данных, помогает предотвращать превышение лимитов.
Ярлыки: база данных (db_name), инстанс (instance).

Number of HTTP 200 for shop API / CRM API / MES API
Зачем нужна: Показывает успешные запросы, позволяет анализировать общее количество запросов.
Ярлыки: сервис (service), метод (method).

Number of HTTP 500 for shop API / CRM API / MES API
Зачем нужна: Показывает количество внутренних ошибок сервера, сигнализирует о возможных проблемах.Ярлыки: сервис (service), метод (method).

Kb transferred (received) for shop API / CRM API / MES API
Зачем нужна: Позволяет отслеживать объем входящего трафика. Высокие значения могут указывать на высокую нагрузку или атаки.
Ярлыки: сервис (service), метод (method).

Kb provided (sent) for shop API / CRM API / MES API
Зачем нужна: Показывает объем отправленного трафика, помогает анализировать сетевую активность.Ярлыки: сервис (service), метод (method).
