## Мотивация 
Логи нужны чтобы разобраться с некорректным поведением системы. Влияет на идентификацию ошибок в системе и их скорейшую правку.
Логи помогают при отладке разных компонентов приложения, а также позволяют собирать и анализировать данные о работе системы. Это помогает обнаружить ошибки. Ещё логи — это один из источников информации для мониторинга.
Мониторинг и логирование преследуют общую цель. Они помогают сформировать представление о состоянии приложения. Если использовать эти подходы вместе, они смогут компенсировать ограничения друг друга и вы получите более полную картину. Например, система мониторинга прислала алёрт. Можно сразу посмотреть ошибки из логов. Тогда вы быстрее установите причину проблемы. 

В первую очередь внедрить логгирование:
1. Mes API
2. Shop API
3. CRM API

Метрики:
1. Время отклика системы 
   - Уменьшение времени отклика способствует улучшению клиентского опыта и повышению уровня удовлетворенности пользователей.

2. Надежность и доступность системы 
   - Повышение доступности системы снижает время простоя и улучшает взаимодействие с клиентами, что способствует повышению доверия и сокращению потерь дохода.

3. Оперативное реагирование на инциденты
   - Снижение времени на реагирование на инциденты помогает минимизировать возможные убытки и повысить удовлетворенность пользователей

2. Политика безопасности в отношении логов

Роли и разрешения:
 - Администраторы (например, роль admin) должны иметь полный доступ ко всем логам и трассировкам.
 - Разработчики могут иметь доступ только к логам и трассировкам своих сервисов.
 - Операторы могут иметь доступ только к бизнес-логам (например, изменения статусов заказов).
 - Пользователи с ограниченным доступом (например, через OAuth2 Proxy) могут иметь доступ только к дашбордам   - Kibana для мониторинга метрик без возможности просматривать сами логи.
  
Защита чувствительных данных
- Логи должны быть очищены от чувствительных данных (паролей, токенов, карты), как на этапе сбора, так и на уровне агрегации.
Для этого можно использовать Logstash фильтры.

 - Шифрование логов:
Логи, передаваемые между сервисами (например, от Filebeat в Logstash), должны быть зашифрованы с помощью TLS для защиты в процессе передачи.

3. Политику хранения в отношении логов

Создать отдельный индекс:
1. Shop API
2. CRM API 
3. MES API 
4. RabbitMQ 
5. Shop DB
6. MES DB
Каждый индекс может быть шардирован для улучшения производительности и масштабируемости.

Логи могут храниться в Elasticsearch согласно следующей политике:
- Логи с уровнем INFO и DEBUG могут храниться 30 дней.
- Логи с уровнем ERROR и FATAL могут храниться до 90 дней для глубокого анализа инцидентов.
- Логи старше указанного времени могут автоматически удаляться, чтобы не перегружать кластер Elasticsearch, с помощью Index Lifecycle Management (ILM).

Ротация индексов:
Индексы могут быть настроены на ежедневную или ежемесячную ротацию, в зависимости от объема логов.
Ротация обеспечит возможность эффективного поиска в актуальных данных и управление старыми данными.

Для долгосрочного хранения можно использовать архивирование логов в S3

Анализ логов становится эффективным только при наличии понятных дашбордов и отчетов.
